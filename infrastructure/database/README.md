# Локальные базы данных

Один PostgreSQL 16 и один SQL Server 2022 Developer в Docker обслуживают все пять подключений проекта. Это окружение разработки: порты опубликованы только на `127.0.0.1`, данные сохраняются в именованных volumes, административные учётные записи используются только локально. SQL Server Developer не предназначен для production.

| Ключ ConnectionStrings | База | Сервер | EF-контексты | Таблицы |
|---|---|---|---|---:|
| LegalPersons | legal_persons | PostgreSQL | LegalPersonsContext из public и private | 16 |
| BureauQBCH | bureau_qbch | PostgreSQL | BureauQBCHContext | 5 |
| BureauData | bureau_data | PostgreSQL | BureauDataContext | 0 |
| BureauUsers | bureau_users | SQL Server | BureauUsersContext | 3 |
| BureauWebUI | bureau_web_ui | SQL Server | BureauWebUIContext из public и private | 2 |

## Первый запуск на Windows: пошагово

Результат шагов 1–5 — работающие базы с таблицами. Сам сайт запускается отдельно, на шаге 6. В Docker работают только серверы баз данных; веб-приложения запускаются через .NET на вашем компьютере.

Выполняйте команды по одному блоку. Если появилась ошибка, остановитесь на этом шаге и найдите её в разделе «Если что-то не получилось» ниже.

### Шаг 1. Откройте Docker Desktop

1. В меню «Пуск» найдите **Docker Desktop** и запустите его.
2. Дождитесь, пока приложение сообщит, что Docker Engine работает. Первое открытие окна ещё не означает, что сервер готов.
3. Используйте режим **Linux containers**. Если в меню Docker есть пункт **Switch to Linux containers**, выберите его. Для образа SQL Server нужен компьютер x86-64.
4. Если Docker Desktop не установлен, сначала установите его и завершите предложенную настройку WSL 2. После установки может потребоваться перезагрузка.

Для запуска только баз данных .NET устанавливать не нужно: SQL-файлы уже подготовлены. Для запуска сайтов понадобится .NET 8 SDK с ASP.NET Core Runtime 8.

### Шаг 2. Откройте PowerShell в папке проекта

Откройте **Терминал Windows → PowerShell** или приложение **PowerShell** через «Пуск». Команды ниже предназначены для PowerShell, а не для командной строки `cmd`.

Перейдите в проект:

```powershell
Set-Location 'C:\Vanya\DEV\job\LK_YuL'
```

Проверьте, что вы в нужной папке:

```powershell
Test-Path .\compose.yaml
```

Ожидается `True`. Если получили `False`, исправьте путь к проекту.

Теперь проверьте Docker:

```powershell
docker version
docker compose version
```

Первая команда должна показать разделы **Client** и **Server** без ошибки подключения. Вторая — версию Docker Compose v2. Если показан только Client и ошибка про `dockerDesktopLinuxEngine`, вернитесь к шагу 1. Пока Server недоступен, запуск баз не сработает.

### Шаг 3. Проверьте файл с паролями

В этой рабочей копии `.env` уже создан со случайными паролями. Проверьте наличие:

```powershell
Test-Path .\.env
```

Если ответ **True**, переходите к шагу 4. Перезаписывать существующий файл не требуется.

Если ответ **False** — например, вы только что скачали репозиторий — создайте его из примера:

```powershell
Copy-Item .\.env.example .\.env
notepad .\.env
```

В Блокноте замените значения двух строк на свои пароли:

```dotenv
POSTGRES_PASSWORD='ваш-пароль-для-PostgreSQL'
MSSQL_SA_PASSWORD='ваш-пароль-для-SQL-Server'
```

Текст выше — обозначение места для пароля. Для SQL Server задайте пароль длиной хотя бы 12 символов с заглавными и строчными латинскими буквами, цифрами и специальным символом. Сохраните одинарные кавычки вокруг значений, а внутри пароля не используйте одинарную кавычку. Оставьте `POSTGRES_PORT=5432` и `SQLSERVER_PORT=1433`, если эти порты свободны. Сохраните файл и закройте Блокнот.

`.env` хранится только локально и исключён из Git. Docker и скрипт подключения приложений читают пароли из этого файла. После первого успешного создания баз простая замена пароля в `.env` не изменит пароль внутри базы.

### Шаг 4. Запустите серверы и создайте базы

В том же PowerShell выполните:

```powershell
.\infrastructure\database\Start-Databases.ps1
```

Скрипт последовательно:

1. Подготовит образы инициализации: скопирует в них SQL-файлы и скрипты. При необходимости скачает базовые образы PostgreSQL и SQL Server. В первый раз это может занять несколько минут; нужен доступ к интернету.
2. Запустит два контейнера и дождётся готовности серверов.
3. Создаст три базы PostgreSQL и две базы SQL Server.
4. Выполнит подготовленные SQL-файлы для создания таблиц.

В конце должна появиться строка:

```text
All five local databases are initialized.
```

После этого проверьте состояние:

```powershell
docker compose ps
```

У сервисов `postgres` и `sqlserver` ожидается состояние `Up` и `healthy`. Временные контейнеры создания схем удаляются после выполнения, поэтому отсутствие `postgres-init` и `sqlserver-init` в списке нормально.

### Шаг 5. Проверьте созданные схемы

```powershell
.\infrastructure\database\Test-Databases.ps1
```

Скрипт проверит повторный запуск инициализации, таблицы, типы и пробные вставки. В конце ожидается:

```text
Database smoke checks passed. Test rows were rolled back (identity sequences may advance).
```

Это означает, что проверки прошли, а тестовые записи отменены. Счётчики идентификаторов могут увеличиться — для локальной базы это нормально.

**На этом развёртывание баз закончено.** Они пока пустые: учётные записи приложения, справочники и рабочие данные нужно загрузить отдельно. Логины `lk_dev` и `sa` предназначены для подключения к серверам БД; через них нельзя войти на сайт. Ограничения внешних функций перечислены ниже.

### Шаг 6. Подключите и запустите сайт — если это нужно сейчас

Пропустите этот шаг, если задача — только поднять базы.

Проверьте установленный .NET:

```powershell
dotnet --list-sdks
dotnet --list-runtimes
```

Для обычного запуска проекта нужны SDK 8.0.x и runtime `Microsoft.AspNetCore.App 8.0.x`. Если их нет, установите .NET 8 SDK. Наличие только SDK 10 не гарантирует наличие runtime 8.

Для публичного приложения выполните в одном окне PowerShell:

```powershell
Set-Location 'C:\Vanya\DEV\job\LK_YuL'
.\infrastructure\database\Use-LocalDatabases.ps1
$env:ASPNETCORE_ENVIRONMENT = 'Development'
dotnet run --project .\public\user_interface_public_web --no-launch-profile --urls http://localhost:5264
```

Скрипт `Use-LocalDatabases.ps1` подставляет адреса и пароли всех локальных БД в настройки текущего окна PowerShell. Ожидается сообщение, начинающееся с `Five ConnectionStrings overrides now point to local Docker databases`.

После запуска приложения дождитесь строки `Now listening on: http://localhost:5264` и откройте в браузере [http://localhost:5264](http://localhost:5264). Терминал оставьте открытым — в нём работает сайт. Параметр `--no-launch-profile` позволяет использовать указанный локальный адрес вместо адреса из существующего профиля запуска.

Для закрытого приложения откройте **второе окно PowerShell** и выполните:

```powershell
Set-Location 'C:\Vanya\DEV\job\LK_YuL'
.\infrastructure\database\Use-LocalDatabases.ps1
$env:ASPNETCORE_ENVIRONMENT = 'Development'
dotnet run --project .\private\user_interface_private_web --no-launch-profile --urls http://localhost:5258
```

Дождитесь `Now listening on: http://localhost:5258` и откройте [http://localhost:5258](http://localhost:5258).

Подключения задаются отдельно в каждом окне: новое окно их не наследует. Уже открытая Visual Studio также их не получит. Для первого запуска используйте команды выше. Для остановки сайта нажмите `Ctrl+C` в соответствующем окне.

Эти команды настраивают подключения к БД и адрес сайта. Для работы бизнес-сценариев дополнительно нужны данные, сертификаты, доступ к пакетам NuGet и внешним HTTP/SMTP-сервисам. Если приложение не собирается или не запускается, это отдельный этап после успешной проверки баз на шаге 5.

## Повторный запуск на следующий день

1. Откройте Docker Desktop и дождитесь готовности Engine.
2. Откройте PowerShell и выполните:

```powershell
Set-Location 'C:\Vanya\DEV\job\LK_YuL'
.\infrastructure\database\Start-Databases.ps1
```

Существующие данные сохранятся. Сообщение `already initialized` означает, что схема уже создана. Копировать `.env` и генерировать SQL заново не нужно. Для запуска сайта повторите шаг 6: настройки подключения действуют только в текущем окне PowerShell.

## Как остановить базы

В PowerShell из папки проекта:

```powershell
docker compose stop
```

Контейнеры остановятся, данные останутся. Следующий запуск — через `Start-Databases.ps1`.

Команда `docker compose down` удаляет контейнеры, сохраняя данные. Данные лежат в Docker volumes — постоянных хранилищах, переживающих удаление контейнера.

## Если что-то не получилось

| Сообщение или ситуация | Что сделать |
|---|---|
| `docker` не распознан | Установите Docker Desktop; после установки откройте новое окно PowerShell. |
| Ошибка подключения к `dockerDesktopLinuxEngine` | Запустите Docker Desktop, дождитесь Engine и повторите `docker version`. Нужен успешный раздел Server. |
| PowerShell сообщает, что выполнение скриптов запрещено | Для текущего окна выполните `Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned`, затем повторите команду. Если политику задаёт организация, обратитесь к администратору. |
| `Create .env from .env.example...` | Выполните шаг 3. Файл должен называться `.env`, а не `.env.txt`. |
| `port is already allocated` / порт занят | До первого запуска откройте `.env`, поменяйте `POSTGRES_PORT` на `5433` и/или `SQLSERVER_PORT` на `1434`, сохраните и повторите шаг 4. Скрипт подключения сам прочитает новые порты. |
| `Database containers did not become healthy` | Выполните команду просмотра логов ниже. Для SQL Server проверьте сообщения о сложности пароля, нехватке памяти или ошибке запуска. После устранения причины повторите шаг 4. |
| Ошибка скачивания образа | Проверьте доступ к интернету и реестрам Docker, затем повторите шаг 4. |
| `sha256sum: /bootstrap/sql/bureau_users.sql: Permission denied` | Обновите `Dockerfile.init`: строка копирования SQL должна быть `COPY --chmod=755 sql/ /bootstrap/sql/`. Режим `644` запрещает пользователю SQL Server проход в каталог. Повторите `Start-Databases.ps1`: он пересоберёт образ. Созданные базы PostgreSQL сохранятся; удалять volumes не нужно. |
| `bash: /bootstrap/postgres/init.sh: No such file or directory` | Проверьте наличие `infrastructure/database/postgres/init.sh`. В старой конфигурации Docker подключал папку проекта напрямую и мог не видеть сетевой диск `M:`. Обновите `compose.yaml`, оба PowerShell-скрипта запуска/проверки и добавьте `infrastructure/database/Dockerfile.init` и `.dockerignore` из исправленной версии. Затем повторите шаг 4. Новый запуск копирует файлы в образы через сборку. Удалять volumes не нужно. |
| `PostgreSQL initialization failed` / `SQL Server initialization failed` | Найдите первую SQL-ошибку выше этой строки в терминале. После исправления причины повторите шаг 4. |
| `Schema changed` | SQL-файлы изменились после создания баз. Нужна миграция либо осознанное пересоздание локальных данных; порядок сброса приведён ниже. |
| `Refusing to bootstrap a non-empty, unmanaged database` | Найдена непустая база, которую этот скрипт не создавал. Проверьте, какие данные там находятся, прежде чем решать вопрос со сбросом. |
| После смены пароля в `.env` возникла ошибка входа | Старый volume сохраняет прежний пароль. Верните прежнее значение в `.env` либо измените пароль внутри БД через `ALTER ROLE` / `ALTER LOGIN`. |
| `You must install or update .NET` при запуске сайта | Проверьте runtime на шаге 6; проект использует .NET 8. |

Логи серверов:

```powershell
docker compose logs --tail 100 postgres sqlserver
```

Вывод инициализации отображается непосредственно в окне, где выполнялся `Start-Databases.ps1`. Временные контейнеры удаляются, поэтому для повторного получения этой ошибки снова выполните скрипт.

## Полностью пересоздать локальные базы

Используйте только если все данные этих пяти локальных баз можно удалить. Например, после изменения схемы на одноразовом тестовом окружении. Для обычного запуска этот раздел не нужен.

1. Остановите сайты через `Ctrl+C`.
2. Из корня проекта выполните:

```powershell
docker compose down --volumes
```

**Эта команда удаляет оба хранилища со всеми пятью базами и их данными.**

3. Создайте базы заново и проверьте их:

```powershell
.\infrastructure\database\Start-Databases.ps1
.\infrastructure\database\Test-Databases.ps1
```

## Подключение через клиент БД

Используйте эти параметры, если хотите посмотреть таблицы через установленный клиент PostgreSQL или SQL Server:

| Параметр | PostgreSQL | SQL Server |
|---|---|---|
| Адрес | `127.0.0.1` | `127.0.0.1,1433` |
| Порт | `5432` | Уже указан после запятой в адресе |
| Пользователь | `lk_dev` | `sa` |
| Пароль | Значение `POSTGRES_PASSWORD` из `.env` без внешних кавычек | Значение `MSSQL_SA_PASSWORD` из `.env` без внешних кавычек |
| База | `legal_persons`, `bureau_qbch` или `bureau_data` | `bureau_users` или `bureau_web_ui` |
| Дополнительно | — | Включите доверие сертификату сервера (`TrustServerCertificate=True`) |

Если меняли порты в `.env`, используйте новые значения. Для приложения внутри сети Compose адреса серверов — `postgres:5432` и `sqlserver:1433`.

## Генерация схемы из EF

```powershell
./infrastructure/database/Generate-Schema.ps1
```

Нужен .NET SDK 8 или новее и NuGet-зависимости проектов. Генератор не подключается к базам: получает миграционные операции из EF-моделей, объединяет описания общих таблиц и формирует SQL соответствующим провайдером. Несовместимые определения одинаковых колонок, ключей и индексов приводят к ошибке. Отдельная сборка `PublicModels` компилирует исходники публичной модели, поскольку две исходные библиотеки имеют одинаковые имена сборок и пространств имён.

В `legal_persons` объединены поля обеих моделей: в том числе `certificates.request_id`, `certificates.legal_person_id`, `organizations.reg_date`, `td_users.sault`, `te_temporary_codes.is_active`. Для обязательных полей, отсутствующих в private, добавлены значения по умолчанию (`0`, пустая строка, `true`), чтобы вставки private не ломались. `organizations.legal_person_id` согласован как `long` / `bigint` в обоих приложениях. В EF зарегистрированы три PostgreSQL enum-типа. CLR-инициализаторы остальных свойств не превращаются автоматически в SQL DEFAULT.

`Results` и `UploadResults` — проекции результатов функций; они исключены из миграций и физические таблицы для них не создаются. `BureauData` получает только служебную отметку инициализации.

SQL в `sql/` — начальная схема для пустых баз, а не миграции существующего окружения. Для применения вручную сначала создайте базы с именами из таблицы и выполните соответствующий файл клиентом `psql` / `sqlcmd`. Скрипты инициализации делают это автоматически. После изменения EF-моделей перегенерируйте SQL, просмотрите diff и подготовьте отдельную миграцию данных либо пересоздайте локальные volumes.

## Что невозможно восстановить из EF

В исходниках нет определений следующих функций:

- PostgreSQL: функция из `Procedures:CreditContractCheck` (в production-конфигурации `custom_tables.creditcontractrecord_uni_v2`; в старой конфигурации встречается `custom_tables.CreditContractRecord3`). Вызывается с UID договора и идентификатором юрлица, возвращает XML.
- SQL Server: `dbo.loader_getUploadResultXmlByKeyId`, вызывается с идентификатором выгрузки, возвращает XML.

Функции и их внутренние таблицы нужно получить из исходной инфраструктуры отдельным SQL-экспортом. Заглушки с вымышленными результатами не создаются. Проверка договора и получение результата выгрузки до установки функций работать не будут. Начальные справочники, пользователи, сертификаты, задания обработки очередей, триггеры и бизнес-данные также не описаны EF и не выдумываются. Базы пустые: готовность схем не означает готовность всех сценариев приложения.

## Проверки

`Test-Databases.ps1` повторно запускает bootstrap, проверяет число таблиц, enum-типы, объединённые поля, bigint-идентификаторы и пробные вставки в обоих провайдерах с откатом транзакций. Значения последовательностей могут увеличиться. Проверка предназначена для этого локального пустого окружения, до импорта внешней схемы BureauData.

Официальная документация: [SQL Server в Docker](https://learn.microsoft.com/en-us/sql/linux/sql-server-linux-docker-container-deployment?view=sql-server-ver17), [PostgreSQL image](https://hub.docker.com/_/postgres), [настройка enum в Npgsql до EF 9](https://www.npgsql.org/efcore/mapping/enum.html#older-ef-versions).
