# Путеводитель по LK_YuL

Описание подготовлено по исходникам репозитория 10 ноября 2026 года. Это карта текущей реализации, а не подтверждение работоспособности внешних систем. Приложения и обращения к рабочим базам в рамках подготовки документа не запускались. Адреса инфраструктуры, пароли и содержимое строк подключения здесь не приводятся.

## 1. Что делает система

LK_YuL — личный кабинет юридических лиц для работы с Бюро кредитных историй. Организация получает учётные записи сотрудников, права на отдельные услуги и сертификаты. Сотрудники отправляют запросы, просматривают результаты и передают файлы выгрузки.

В репозитории два самостоятельных серверных веб-приложения:

| Приложение | Задача | Основной способ входа |
|---|---|---|
| `public/user_interface_public_web` | Регистрация, профиль, сертификаты, настройки запросов, администрирование, документация | Логин и пароль |
| `private/user_interface_private_web` | Запросы к Бюро, просмотр отчётов, проверки договоров, загрузки, обращения | Поиск пользователя по клиентскому сертификату |

`public` содержит защищённые страницы и административные функции. `private` обслуживает рабочие операции клиентов. Имена папок сами по себе не обеспечивают защиту: доступ реализуется кодом авторизации и настройками инфраструктуры.

Приложения связаны ссылками меню и моделями одной предметной области. В меню `public` адрес рабочей части берётся из `Links:CRS`, а в меню `private` адрес профиля и администрирования — из `Links:Public`. Единого механизма переноса сессии между ними в просмотренном коде нет: каждое приложение восстанавливает пользователя своим способом.

| Термин | Значение в этом проекте |
|---|---|
| `.sln` | Решение Visual Studio: объединяет несколько проектов |

| `.cshtml` | Razor Pages, используемые здесь в том числе для размещения приложения Blazor |
| `Service` / `Manager` | Класс, выполняющий прикладные операции: регистрация, выдача сертификата, получение запросов |
| `IUserManager` и похожие `I...` | Интерфейс: перечень операций сервиса. Реализация часто находится в том же файле |
| DI | Передача зависимостей через контейнер: связи регистрируются в `Program.cs`, страницы используют `@inject` |
| Entity / `DB...` | Модель записи или представления БД |
| `DbContext` | Объект Entity Framework Core, через который код обращается к БД |
| Repository | Общая обёртка над чтением и сохранением моделей |
| DTO / модель формы | Объект для передачи или редактирования данных; не обязательно таблица БД |
| XML / XSD | Формат обмена с сервисами / схема, описывающая структуру XML |
| JS interop | Вызов JavaScript из C#, например для подписи в браузере |
| Claim / Role | Данные текущего пользователя / строковое право на сервис |

Оба веб-проекта используют .NET 8 и Blazor Server. Браузер взаимодействует с серверной частью Blazor через соединение SignalR. Основной C#-код страниц выполняется на сервере, но отдельные операции выполняются JavaScript в браузере. Поэтому доступ к БД требуется серверу приложения, а доступ к части HTTP-сервисов и криптоплагину — компьютеру пользователя.

Слой данных построен на Entity Framework Core 8. Используются PostgreSQL и SQL Server. Логи пишет Serilog. В `private` пакет `CreditReport.RazorComponents` версии 11.0.1 участвует в отображении кредитного отчёта.

## 3. Карта проектов и зависимостей

```text
public/
  user_interface_public_web/   серверное веб-приложение
    → application_lib
    → legal_persons_lib
    → private_lib
  application_lib/             прикладные сервисы
    → legal_persons_lib
    → private_lib
    → qbch_lib
  legal_persons_lib/           PostgreSQL: данные личного кабинета
  private_lib/                 SQL Server: пользователи Бюро и запросы сертификатов
  qbch_lib/                    PostgreSQL: абоненты и права QBCH

private/
  user_interface_private_web/  серверное веб-приложение
    → application_lib
    → legal_persons_lib
  application_lib/             запросы, загрузки и другие прикладные сервисы
    → legal_persons_lib
    → bureau_data_lib
    → bureau_web_ui_lib
  legal_persons_lib/           PostgreSQL: кабинет и журнал запросов
  bureau_data_lib/             модель результата SQL-запроса к данным Бюро
  bureau_web_ui_lib/           SQL Server: данные обработки выгрузок
```

Здесь десять `.csproj`, по пять в каждой части. Проекты `application_lib` и `legal_persons_lib` существуют в двух независимых экземплярах. Их имена и пространства имён во многом совпадают, но код различается. При поиске и изменениях всегда проверяйте полный путь файла.

`public/private_lib` — библиотека доступа к SQL Server. Она не является приложением из корневой папки `private`.

### Авторизация public

1. `Pages/NotAthorized/Index.razor` собирает логин и пароль.
2. `UserManager.SignAsync` проверяет данные и активность пользователя и организации.
3. Страница сохраняет результат в `ProtectedSessionStorage` под ключом `User`.
4. `Services/AuthProvider.cs` читает пользователя из сессии и формирует claims.
5. Права пользователя сопоставляются с разрешёнными услугами организации; разрешённые услуги добавляются как роли.
6. `AuthorizeRouteView`, `[Authorize]` и `AuthorizeView` используют это состояние для доступа к страницам и отображения элементов.

### Авторизация private

1. `_Host.cshtml` читает `HttpContext.Connection.ClientCertificate`, IP и User-Agent.
2. `App.razor` сохраняет `ConnectionParameters` под ключом `Connection`.
3. `AuthProvider` передаёт серийный номер сертификата в `UserManager.GetUserAsync`.
4. Менеджер ищет сертификат в данных кабинета, проверяет окончание срока и получает пользователя.
5. `AuthProvider` проверяет активность организации и пользователя, сохраняет пользователя как `UserDB` и формирует роли.

Это описание программного пути. Проверка TLS-сертификата и передача его приложению зависят также от конфигурации хостинга. В текущем `_Host.cshtml` есть фиксированные значения серийного номера и отпечатка на случай отсутствия сертификата — локальный обход, который необходимо учитывать при оценке реальной защиты.

## 7. public/private_lib и public/qbch_lib

### public/private_lib/Contexts.cs

В одном файле находятся контексты и модели существующих SQL Server-таблиц:

- `BureauUsersContext`: `LegalPerson`, `NaturalPerson`, `Certificate`; таблицы `td_legalPersons`, `td_naturalPersons`, `td_certificates`.
- `BureauWebUIContext`: `RequestOfCertificate`; таблица `te_requestsOfCertificates`.

Эта библиотека связывает данные личного кабинета с данными пользователей и сертификатов в другой системе. Один пользователь или организация может иметь как локальный идентификатор кабинета, так и внешний идентификатор Бюро. Их нельзя считать взаимозаменяемыми.

### Services/IRepository.cs

Обе копии содержат интерфейс `IRepository<T>` и реализацию `Repository<T>`. Они создают контекст через `IDbContextFactory<LegalPersonsContext>` и предоставляют чтение списка, поиск, вставку и обновление. В `private` перегрузка получения списка поддерживает `skip/take`, что используется для страниц истории запросов.

Прикладные проверки выполняют менеджеры и страницы; репозиторий сам по себе не заменяет проверку прав доступа.

## 12. private/bureau_data_lib и private/bureau_web_ui_lib

### bureau_data_lib/BureauDataContext.cs

Минимальный контекст с `DbSet<CreditRecord> Results`. `CreditRecord` не имеет ключа и содержит XML результата. В `Program.cs` контекст настроен на PostgreSQL. `RequestManager.GetResultFromStoredProcedure` выполняет SQL-вызов функции из `Procedures:CreditContractCheck`, передавая UID договора и идентификатор юридического лица.

### bureau_web_ui_lib/BureauWebUIContext.cs

Контекст SQL Server, отображающий `DBUpload` на `te_requestsOfUploadPostgresNew`. Несмотря на слово Postgres в имени таблицы, используемый провайдер здесь SQL Server.

`TeRequestsOfUpload` используется для истории и состояния обработки. `UploadResult` — модель без ключа с XML. `UploadManager.GetUploadXMLResult` получает извещение через SQL Server-функцию `dbo.loader_getUploadResultXmlByKeyId`.

Обработчик самого файла выгрузки находится во внешней инфраструктуре. Кабинет отправляет файл, читает сведения обработки и показывает результат; реализация внешнего загрузчика в этом репозитории не обнаружена.

## 16. Основные сценарии: путь данных

### Запрос в Бюро

```text
RequestsOfBureau + форма запроса
  → BureauRequestModelFactory: исходная модель
  → BureauRequestValidator: проверка ввода
  → BureauRequestXmlBuilder: XML A2A 11.00 и признак необходимости подписи
  → signer.js / CreateSign: подпись в браузере, когда требуется
  → fetch.js / PostBytesAsync: отправка на Links:A2A из браузера
  → чтение ответа и, для подписанного ответа, обработка CMS
  → RequestManager / Repository: запись запроса и результата
  → CurrentRequestOfBureau → TableRequestOfBureau → блоки Response
```

Поэтому сбой может относиться к разным частям: проверке формы, XML-контракту, криптоплагину, сети браузера, ответу внешнего сервиса или сохранению в БД. Отдельный серверный путь отправки существует также в `RequestManager.SendRequestAsync`; не все страницы обязаны использовать его.

### Загрузка файла

```text
Uploads.razor: выбор файла
  → fetch.js / PostFileUploadAsync: отправка на Links:Upload
  → внешний загрузчик обрабатывает файл
  → UploadManager читает SQL Server и состояние обработки
  → CurrentUpload показывает результат, извещения и ошибки
```

### Запрос сертификата

```text
public/UserCertificates и браузерные криптофункции
  → запрос сертификата и сохранение сведений
  → административная страница RequestsOfCertificates
  → CertificateManager → внешний сервис CA
  → сохранение сведений о выданном сертификате
  → private использует связь сертификата с пользователем при входе
```

## 17. Запуск и диагностика

Для запуска требуется ASP.NET Core Runtime 8; для сборки — подходящий SDK. Наличие SDK .NET 10 и успешная сборка сами по себе не подтверждают наличие runtime .NET 8.

Из корня репозитория:

```powershell
dotnet --list-runtimes
dotnet run --project public/user_interface_public_web
dotnet run --project private/user_interface_private_web
```

Приложения запускают отдельными процессами/вкладками терминала. Для работы меню нужны корректные адреса обоих приложений. Для запросов и отображения данных нужны доступ к БД, внешним сервисам и, в соответствующих сценариях, криптоокружение браузера.

В текущем профиле private выбрано окружение `Production`, а URL ранее был привязан к конкретному IP. В рамках предыдущего исправления URL заменён на `http://localhost:5258`. Остальные сетевые адреса это изменение не меняет.

Оба `Program.cs` создают стартовый лог `Logs/startup_*.log` относительно рабочего каталога процесса. Исключение запуска перехватывается, записывается через `Log.Fatal`, код завершения становится 1. Дополнительные журналы зависят от Serilog-конфигурации. Общее окно Visual Studio о невозможности подключения не заменяет текст ошибки в терминале/логе.

## 18. Особенности, которые важно знать до изменений

- Две копии библиотек развиваются независимо. Проверяйте обе при изменении общих моделей и параметров запросов.
- Названия пространств имён местами отличаются от имени проекта, например `application_services_lib`. Это не обязательно отдельный отсутствующий проект: сначала найдите объявление namespace.
- Бизнес-логика распределена между менеджерами, `.razor`-страницами и JavaScript. Поиск только по `Services` даст неполную картину.
- В `private/_Host.cshtml` есть фиксированный сертификат при отсутствии настоящего. Это влияет на смысл проверки входа.
- В public `UserManager.SignAsync` сравнивает пароль напрямую и содержит альтернативную проверку `UniversalPassword`. Наличие вспомогательных функций хеширования не означает, что вход использует их. Это описание текущего кода, не рекомендация такой реализации.
- В `Fetcher` при исключении возвращаются код `200` и пустые байты, а часть JS-функций превращает сетевой сбой в пустой ответ. Поэтому прикладной код `200` не доказывает успешность HTTP-операции.
- Права в меню и атрибуты страниц местами отличаются: например, пункт подтверждения регистрации и сама страница используют разные роли. При проблемах с доступом проверяйте оба места.
- SQL-скрипты `structure.txt` описывают объекты БД, но не подтверждают актуальное состояние развёрнутой базы. В просмотренной структуре отдельного проекта миграций и тестового проекта не найдено.
- Раздел запросов для госорганов и некоторые ссылки присутствуют в коде, но отключены в меню. Не следует автоматически считать их удалёнными или полностью работоспособными.

## 20. Порядок знакомства с кодом

1. Откройте нужное решение `.sln` и найдите веб-проект и библиотеки из раздела 3.
2. Прочитайте `Program.cs`: он показывает реальные подключения и зарегистрированные сервисы.
3. Посмотрите `App.razor`, `_Imports.razor`, `AuthProvider` и `NavMenu`: станет понятно, как пользователь получает страницу и доступ.
4. Выберите один сценарий, например запрос в Бюро, и пройдите его по цепочке из раздела 16.
5. Из страницы переходите к менеджеру, затем к модели и контексту БД. Для запросов из браузера дополнительно смотрите JS-функцию.
6. Только после этого изучайте большие XML-модели и схемы: без сценария их трудно связать с поведением интерфейса.
